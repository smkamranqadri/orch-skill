## Registry

One file, `${XDG_STATE_HOME:-~/.local/state}/orch/registry.json`, every read-modify-write under
`fcntl.flock` on `registry.lock` beside it, written by temp file + rename.

```json
{"version": 1,
 "orchs":  {"<session>/w1:p1": {"project": "/abs/repo", "name": "orch-1", "kind": "claude",
            "workspace": "w1", "tab": "w1:t1", "status": "idle", "gone": false,
            "queue": ["[orch] reviewer-1 done · pane w1:p2 · read: herdr agent read reviewer-1"]}},
 "agents": {"<session>/reviewer-1": {"pane": "w1:p2", "orch": "<session>/w1:p1",
            "project": "/abs/repo", "kind": "codex", "model": "gpt-6.1-sol", "effort": "medium",
            "where": "pane", "writes": false, "tree": "/abs/repo", "branch": null,
            "worktree": null, "role": "review", "created": ["pane:w1:p2"], "state": "live",
            "status": "working", "since": 1760000000}}}
```

- Every key is prefixed with `$HERDR_SESSION`, so two Herdr sessions never collide.
- Project = the parent of `git rev-parse --path-format=absolute --git-common-dir`, so a linked
  worktree resolves to its main repo. Tree = `git rev-parse --show-toplevel`, the checkout.
- Agent `state`: `starting` (reserved, resources being made), `live`, `closed`. `created` lists
  the panes, tabs and workspaces orch made for it; close removes only those.
- An orch is gone when `gone` is true; its agents are orphaned until adopted. A gone orch's queue
  is kept for its adopter.

## CLI

```text
orch register [--name N]      register $HERDR_SESSION/$HERDR_PANE_ID as orch of its project
orch spawn NAME --role plan|build|review|explore --kind claude|codex [--model M] [--effort E]
           --where pane|tab|worktree [--writes] [--base REF] --brief FILE
orch list [--all] [--idle] [--role R]   this orch's agents (or every project), grouped by role
orch board                    the board text (what the pane renders)
orch close NAME [--keep-checkout] [--discard]
orch deregister               mark this orch gone (used by orch:close)
```

Every command fails with one clear line and exit 1 outside Herdr (`HERDR_ENV` unset) or when the
caller is not a registered orch (except `register`). Every command, after its own work, retries
delivery of any queue that is pending (see Hook, Deliver).

**register** is idempotent: registering a pane that is already an orch changes nothing. It first
reconciles liveness: each non-gone orch of the project whose pane is no longer in `herdr pane list
--workspace <ws>` is marked gone. Then it adopts, in one locked write, every agent of the project
whose orch is gone: the agent's `orch` becomes the caller, the gone orch's queue moves to the
caller, and one notice per adopted agent with its current status is queued. Then it opens the
board if none is open: `herdr plugin pane open --plugin orch --entrypoint board --placement split
--target-pane $HERDR_PANE_ID --direction right --cwd <project>` (the response gives the board
pane; reads are verified in phase 4).

**spawn**:

1. Under the lock: refuse a name already in the registry as `starting` or `live`, or live in
   `herdr agent list`; with `--writes`, refuse when a `starting` or `live` writer has the same
   tree. Write the agent as `starting`. `--where worktree` implies `--writes` with its own tree.
2. Create the location, recording each made resource in `created`:
   - pane: `herdr pane split --pane $HERDR_PANE_ID --direction right|down --cwd <tree>
     --no-focus` (right when `herdr pane layout --pane $HERDR_PANE_ID` shows a wide pane); new
     pane at `.result.pane.pane_id`.
   - tab: `herdr tab create --workspace $HERDR_WORKSPACE_ID --cwd <tree> --label NAME
     --no-focus`; pane at `.result.root_pane.pane_id`.
   - worktree: `herdr worktree create --workspace $HERDR_WORKSPACE_ID --cwd <project>
     --branch orch/NAME --base <REF or HEAD> --path ../<repo>.wt/NAME --label NAME --no-focus`;
     pane at `.result.root_pane.pane_id`, workspace at `.result.workspace.workspace_id`.
3. Store the pane on the agent, then `herdr agent start NAME --kind K --pane P -- <host args>`:
   claude `--model M --effort E`; codex `-m M -c model_reasoning_effort=E` (each only when
   given). Then `herdr agent prompt NAME "<brief>"` (no --wait). Mark `live`.
4. On any failure in 2 or 3: close what `created` lists (and `herdr worktree remove --workspace
   <ws>` a made worktree, never `--force`), drop the reservation, print the failing step, exit 1.

**close**: preflight first, change nothing until it passes. For a worktree agent: the branch is
an ancestor of the orch's HEAD (`git merge-base --is-ancestor`) and `git -C <worktree> status
--porcelain --ignored` is empty; otherwise refuse and print the unmerged commits and the dirty
paths. `--discard` skips both checks. Then in order: `herdr agent send-keys NAME ctrl+c` and
close the panes, tabs and workspaces in `created`; unless `--keep-checkout`, `herdr worktree
remove --workspace <ws>` the checkout and `git branch -d orch/NAME` (`-D` only with `--discard`); mark `closed`.
A failure part-way leaves the agent in the registry with the failed step printed. `orch:close`
runs each removal only after the user says yes.

## Hook

Every event, under the lock:

1. Resolve the pane to a registry entry by `$HERDR_SESSION` + pane; unknown panes are ignored.
2. Read the live status with `herdr agent get <pane>` instead of trusting the event payload's
   order. If the agent is gone, treat it as `pane.closed`.
3. Agent: when the live status differs from the stored one and is done, idle or blocked, append
   `[orch] NAME S · pane P · read: herdr agent read NAME` to its orch's queue (or keep it on the
   gone orch for adoption). A change between done and idle is not a notice. Store the status.
4. Orch: store its live status.
5. Deliver (also run by every CLI command): for each orch that is not gone and has a non-empty
   queue, take its live status from `herdr agent get`; only when idle or done run `herdr agent
   prompt <orch pane> "<queue lines joined by newline>"`. On exit 0, clear the queue and store the
   orch as `working`, so no other delivery runs before a real idle event. On any error keep the
   queue. Delivery is at least once: a crash between prompt and clear can repeat a notice, never
   drop one.

On `pane.closed` (P): an agent gets status `closed` and a notice; an orch is marked gone, its
queue kept. The hook never raises: errors go to stderr, exit 1. Known gap: the user typing into
the orch pane in the instant between the status read and the prompt.
